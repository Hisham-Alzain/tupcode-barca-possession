# Generality audit of the code and its constants (L23, cold, report-only)

Question: would `src/possess/` label a different match of the same kind correctly, or is it shaped around Barcelona vs Athletic (tactical tracking, 41% hidden ball, low-passed ball, this Smart Tagging file)? This audit reads the code and its constants. Seed selection and the learned models are in `docs/overfit-audit.md` and are not repeated.

**Verdict.** The decoder core (`pipeline.label`) is match-agnostic: it runs on any number of periods, on a raw or a smoothed ball, with or without ball. The wrapper around it (`pipeline.run_challenge`) is a one-match program: frame count, graded halves, frame rate and file layout are constants, so a second match cannot be run without editing source. Inside the decoder, three regime switches and the set-piece rule were sized on this match's INPUT statistics; none uses labels, but two of them sit close enough to their thresholds to count as fragile.

Severity: **WOULD BREAK** = wrong or no output on another match of the same kind; **FRAGILE** = works here, flips or degrades silently under a plausible change; FINE items are left out unless the brief asked about them.

Checks: synthetic, no match data (`pipeline.label` on random tracks with 2 and 4 periods, a half without ball, no ball at all; `ball_smoothed` at 10 / 25 / 50 fps; `prior_shift` at 39,999 / 40,001 frames; tag files with unknown types and missing fields). One INPUT-only read of the cached provided features for the margins in section 2 (through `ramlock`; no truth, nothing written).

## 4. Flags and dead code

- Default decoder config: **37 keys** (`pipeline.DEC` = 9 in `DEC_BASE` + 31 in `shape.DEC_SHAPE`, 3 shared). `TAGS`: **8 keys**. Behaviour switches that are ON by default: `hard_dead, soft, duel, smooth_touch, ed_exit, sd_prior, reappear, vtx, ctl_s, ctl_hi, w_fly, ed_cross, ed_cross_strict, ed_xdead, w_bt, w_bd, ed_still` (17) plus `sp, sp_hid` (2).
- **Default-on with an untested off-switch: `sp`, `sp_hid`, `sp_take_s`.** No test calls `run_challenge` or `setpiece_rows`; `tests/test_a8_smarttags.py:96` asserts only `w_tag == 0` and `w_tagr == 0`. `tests/test_setpiece.py` covers the module, not the wiring, and the module's own defaults differ from the pipeline's (`setpiece.SP`: `hid=0, take_s=2.0`; `pipeline.TAGS`: `sp_hid=1, sp_take_s=0`), so a direct caller of `setpiece.apply` gets a different rule. The other 17 switches are named in tests; I did not check test by test that each is exercised at 0.
- Opt-in arguments read by `decode_halves` that the default never sets (about 25): `ed_rkick, ed_rk_line, ed_rk_reapp, ed_rk_law, ctl_hid, w_rev, rev_thr, rev_lag, gap_cp, cp_win, cp_lag, w_tag, tag_vis, w_tagr, tagr_hold_s, tagr_anchor, ed_cross_off, ed_xdead_m`, the `cleanup.KEYS`, `DEAD2 still_v / v_kick`.
- Dead in the default path: `cleanup.py` (148 lines), `react.py` (134 lines; `decode.py:658` "T88 rejected; kept"), `edges.restart_dead` (80 lines), `ball_fill/`, `smarttags.phase_prior / restart_prior / challenge_inputs`.
- Silent fallbacks that change the system without a message: `label()` without `"pos"` runs `DEC_BASE` (`pipeline.py:65-66`: no shape, no learned evidence, no post-passes); `w_bd` / `w_bt` do nothing when their `MODEL` is empty (`decode.py:605,640`); `--tags` accepts any key, so a typo (`sp_hidd=1`) is ignored (`pipeline.py:238`); a missing home name switches the set-piece rule off (`pipeline.py:201-203`) although the default does not use the team.
- Stale text that states the opposite of the default: `setpiece.py:1` ("opt-in, OFF by default"), `smarttags.py:1` ("every flag off by default"), `pipeline.py:143` and `:233` ("OFF by default" / "default off"), and the "opt-in, 0 = off" comments in `decode.py:556-572` for flags that are on.

## Must mention in the technical document as a limitation

1. The entry point runs the provided match only: frame count and graded halves are constants from DATA.md, frame rate and pitch size are constants although the metadata carries them. Another match needs those four values supplied.
2. The system is built for a tactical feed with nearly all players tracked and a calibrated pitch (line rules at 0.5 m). It was not tested on broadcast tracking.
3. Two regime switches read the ball track's smoothing (acceleration p99 against 150 and 70 m/s2). The values were set on external matches smoothed to resemble the provided input; the second threshold separates a gain from a loss with one calibration point on each side.
4. The hidden-frame prior switches on only above 40,000 hidden frames with shape evidence: a hard step.
5. The set-piece rule depends on this Smart Tagging product: its window (-3..+15 s) and 15 s fill come from this file's input inventory, it covers goal kicks, corners and throw-ins only, and only the tagged ones. Without a tag file the pipeline still runs but loses that rule and the pre-kick-off D frames.
6. After decoding, D can only be added by the line, still-ball and set-piece rules; the control pass is not run again.
7. The benches that gated every step since L2-20 imitate this match's input degradation (41% hidden, gap histogram, smoothing). No labels were used, but the selection environment is this match's.

## Worth generalising after the hackathon, in priority order

1. Per-match configuration: halves, frame count, fps and pitch from arguments or metadata; fail loudly on dropped frames, multiple glob hits, malformed tags (1.1-1.5, section 5).
2. One restart rule for all restarts: make the tag-free `edges.restart_dead` the base, tags as optional confidence; add kick-offs after goals and free kicks; one spot geometry with the 9.16 m fix (3.1, 3.2, 3.6).
3. Replace the two smoothing thresholds and the fixed `SMOOTH_TOUCH` by parameters that follow the measured smoothing continuously; express every frame constant in seconds (2.1-2.3, 1.3).
4. Smooth the `sd_prior` cliff (2.4).
5. Feed line crossing, still ball and set pieces to the decoder as emissions instead of post-pass overwrites; one control pass at the end (3.3-3.5, 3.8).
6. Delete the dead paths and the about 25 unused opt-in arguments; fix the stale "off by default" text; add a pipeline-level test for `sp=0` (section 4).
7. Validate on a second real match with its own tag file and on a broadcast-style input before claiming generality.
